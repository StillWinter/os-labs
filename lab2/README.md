# Лабораторная работа №2

Моделирование игры в кости методом Монте-Карло. Выполнила Старыгина А.М.,
М8О-210БВ-25. Преподаватель: Бахарев В.Д.

## Сборка и запуск

Из этой папки:

```sh
make
./main -k 20 -r 11 -a 70 -b 75 -n 200000 -t 14
```

Аргументы передаются в указанном порядке:

- `-k` — общее количество туров K;
- `-r` — текущий тур, который ещё предстоит сыграть;
- `-a` — уже набранные очки первого игрока;
- `-b` — уже набранные очки второго игрока;
- `-n` — количество моделируемых завершений игры;
- `-t` — максимальное количество потоков, включая основной;
- необязательный `-s` — пауза для просмотра потоков средствами ОС.

В примере сыграно 10 туров из 20, поэтому осталось 10. В каждом оставшемся
туре каждый игрок бросает две кости. В конце сравниваются итоговые очки.
Победы первого, победы второго и ничьи учитываются отдельно. Их количества
в сумме равны `-n`, а вероятности до округления дают 100 %.

При `-r 1` игра ещё не началась; при `-r K+1` она уже закончилась.
Параметры — целые числа типа int. Очки допускают ноль, число экспериментов
положительно, лимит потоков — от 1 до 1024. Фактическое количество потоков
не превышает числа экспериментов.

## Файлы

- `main.c` — аргументы, измерение времени и вывод;
- `game.h` — параметры игры, счётчики результатов и объявления функций;
- `game.c` — броски костей и последовательное моделирование;
- `parallel.c` — разделение экспериментов и POSIX Threads;
- `Makefile` — сборка и просмотр потоков;
- `210_Старыгина_Лаб2.docx` и `output/pdf/210_Старыгина_Лаб2.pdf` — отчёт.

## Как работает программа

Для каждого эксперимента берутся исходные очки и моделируются все оставшиеся
туры от `r` до `K` включительно. Затем увеличивается один из трёх счётчиков.
Вероятность исхода оценивается как его частота: число исходов делится на `N`.

Случайные значения создаются через `rand_r` с отдельным состоянием для каждого
эксперимента. Начальное состояние зависит от номера опыта:
`seed = (i + 1) * 2654435761u`. Фиксированный нечётный множитель распределяет
соседние номера по разным состояниям генератора. Переполнение беззнакового
числа здесь предусмотрено. Количество потоков на состояние генератора не влияет.
Поэтому на одной системе результаты двух версий совпадают точно. Между разными
реализациями `rand_r` на разных ОС одинаковые числа не гарантируются.

Для кости используется остаток от деления на 6 плюс 1. Перед этим значения из
лишнего хвоста диапазона генератора отбрасываются, чтобы число допустимых
значений было кратно 6. Это исключает дополнительное смещение от операции `% 6`.

Параллельная версия распределяет номера экспериментов между потоками.
Каждый поток использует собственные счётчики. После `pthread_join` основной
поток складывает их. Мьютекс не нужен, поскольку совместных записей в один
счётчик нет. При p участниках создаются p−1 новых потоков; часть №0 выполняет основной.

Сообщение `Проверка: OK` означает совпадение всех трёх счётчиков последовательной
и параллельной версий. Повторный запуск с теми же параметрами использует ту же
псевдослучайную выборку и служит новым замером времени, а не новым набором опытов.

## Просмотр потоков

На macOS:

```sh
make stats THREADS=14
```

Каждый участник делает паузу 6 секунд перед вычислением; `ps -M` показывает
основной поток и 13 созданных. В режиме `-s` время не выводится.

На Linux:

```sh
./main -k 20 -r 11 -a 70 -b 75 -n 10000 -t 14 -s &
pid=$!; sleep 2; ps -L -p "$pid"; wait "$pid"
```

## Измерения

Время измеряется через `clock_gettime(CLOCK_MONOTONIC, ...)`. В него входят
генерация бросков и подсчёт результатов, а для параллельной версии также создание
потоков, ожидание и объединение счётчиков. Разбор аргументов, вывод и сравнение
двух результатов находятся вне измеряемых участков.

Ускорение `S = Tseq / Tp`. Эффективность `E = S / p * 100%`.
Здесь Tseq — последовательное время, Tp — параллельное, p — фактическое
количество участников вычислений, включая основной поток.

В отчёте использованы реальные замеры на Apple M4 Pro с 14 логическими ядрами:
1, 2, 4, 8, 14, 64, 128 и 1024 потока, по три запуска каждого варианта.
Исследованы разные количества экспериментов и оставшихся туров. На другой
системе измерения нужно повторить относительно её числа логических ядер.

В основных таблицах общий Tseq усреднён по всем 24 последовательным замерам
соответствующего набора. Tp усреднён по трём запускам с данным числом потоков.
Вывод самой программы рассчитывает показатели по двум замерам конкретного запуска.
